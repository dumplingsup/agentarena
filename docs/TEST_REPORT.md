## 关键测试证据

- 预算超限、重复/未知/过多技能、伪造属性被拒绝；自然语言“无敌”不会改变实际能力。
- 测试近战与远程射程、遮挡、掩体减伤、BFS 路径、地图边界、占用格、禁锢限制。
- 验证伤害、护盾、防御、回复、药剂次数、资源消耗与恢复、技能冷却和爆炸灼烧/逃离。
- 生命耗尽、行动上限、剩余生命比例和相同比例平局有固定结果。
- 四预设全部 **16 种对阵** 自动结算；每一步记录动作后重执行，事件、快照、随机状态逐项相同，输入未被修改。
- Pi Agent Core 使用模拟提供商消息执行真实工具，确实推动引擎一次；非法工具得到错误后可重试；未知 Shell 工具与属性伪造被拒绝。
- 观察、工具与模型次数有上限；同一回复多个动作只允许一次有效执行；超时、取消、模型故障、上下文和 Token 预算均有明确失败。
- 两个 Agent 的私有 Prompt 不互传；编辑后的特定 Prompt 确实出现在各自模型请求中；战场观察不包含对手背景与 Prompt。
- 本地 HTTP/SSE 模拟端点通过 **Pi 实际 OpenAI-compatible 适配器**接收服务端 Authorization、模型消息与六个工具 Schema，返回工具调用后由引擎执行；用量记录等于端点报告的 `241 tokens`。这是协议集成测试，**不是外部真实模型实测**。
- SQLite 保存角色版本与不可变比赛快照；之后编辑不改变历史参赛配置。比赛重复结算、重复运行不会重复入账；Demo/LLM 分榜；自对战不计积分；取消与服务中断比赛可重试。
- API 创建、复制、非法输入、同源验证、无凭据配置响应、异步完成与历史列表均经过 HTTP 实测。
- 浏览器确认 Prompt 保存后刷新仍存在，比赛结果与工具执行可见；暂停/单步/跳转与历史入口工作，无浏览器运行时异常。

## 测试中修复的问题

安装包实际为 Pi 1.4.0，按其新 `Agent`/provider/TypeBox 声明确认 API。修复了工具参数的 TypeScript 类型和测试 JSON 类型。浏览器首轮等待受安装期间的 watch 启动影响，测试服务改为不启用 watch 的同一开发入口；发现导航选择器会同时匹配头像入口，改为限定 navigation。截图统一回到顶部并关闭动画，避免将过渡中的 HP 条误当最终状态。

## 尚未证明的部分

当前环境未发现可用模型 API Key，因此没有真实外部 LLM 对战、实际厂商计费或真实模型 Prompt 优势的测试证据。Pi 工具循环、HTTP 协议、提示词传递与错误恢复已有自动化验证；填入有效 Key 后仍需执行至少一场完整对战与成对策略评测。不同提供商兼容性、思考等级、模型质量和长期竞技平衡均需真实实验。少量 Demo 比赛不证明 Prompt 能提高胜率。
